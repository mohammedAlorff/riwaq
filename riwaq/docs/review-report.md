# مراجعة رواق

التقسيم محفوظ: `رواق.html` للطلاب، `presidents/` للرؤساء، و`admin/`
للأدمن. صفحات منفصلة تشترك في API، والتحقق من الدور وملكية النادي
يحدث في الخادم. الفصل بين المسارات وحده ليس حاجز الصلاحيات.

## الإصلاحات

- ربط CSRF بالجلسة؛ مطابقة كوكي وترويسة يختارهما العميل لم تعد كافية.
- منع تزوير عنوان العميل عبر ترويسات البروكسي غير الموثوق.
- منع طلبات القراءة من مسح عدّاد محاولات تسجيل الدخول قبل انتهاء مدته.
- توحيد توقيت انتهاء الجلسة بين قاعدة البيانات والكوكي، وتحديث رموز
  الجلسات السابقة عند إعادة تحميل لوحة الإدارة.
- وضع تغيير كلمة المرور وإبطال الجلسات في معاملة واحدة.
- إعادة فحص بصمة كلمة المرور بقفل صف المستخدم قبل إصدار الجلسة، لمنع
  تسجيل دخول قديم كان قيد التنفيذ من تجاوز تغيير كلمة المرور. لا تُرسل
  كوكيز الدخول إلا بعد نجاح المعاملة.
- تسلسل تخصيص معرفات الأندية بقفل MySQL مسمّى خاص بقاعدة البيانات، مع
  مهلة انتظار محدودة، دون تعديل المعرفات الحالية أو مخطط قاعدة العمل.
- معالجة تعارض إنشاء الحسابات والأندية المتزامن برد JSON بحالة 409،
  والتراجع عن النادي إذا تعارض اسم المستخدم، بدل ترك نادي بلا حساب.
- تحويل الاستثناءات غير المعالجة إلى JSON بحالة 500 ورسالة عامة، دون
  كشف استعلامات SQL أو المسارات أو تتبع الاستدعاءات للزائر.
- تطبيق حدّ الكتابة على إدارة الحسابات والأندية أيضًا.
- رفض أنواع JSON غير المناسبة، والأجسام الكبيرة، والروابط المشوّهة،
  والتواريخ غير الموجودة، والأوقات غير الصحيحة، والمقاعد غير الصحيحة.
- رفض معرّفات الحذف المختلطة مثل `12abc` والحقول المطلوبة الفارغة.
- تقييد كلمات المرور الجديدة بحد bcrypt البالغ 72 بايت حتى لا تُقطع بصمت.
- جعل تهيئة قاعدة البيانات من CLI فقط، وحماية ملفات التطوير والاختبار
  ومخرجات التهيئة في إعدادات Apache وخادم التطوير.
- قصر مجلد الرفع على الصور، وتجنب إعداد PHP غير المحمي تحت Apache/FPM.
- إصلاح `/admin` و`/presidents` بإعادة التوجيه إلى المسار المنتهي بشرطة.
- إصلاح اقتباس مسار امتدادات PHP في ملف تشغيل ويندوز عندما يحتوي المسار مسافات؛
  يمكن التحقق من تحميلها دون تشغيل موقع جديد باستخدام `start-dev.bat --check`.
- إصلاح الروابط التي تحتوي وسومًا مرمّزة أو ترميزًا غير صالح في صفحة الطلاب.
- إبقاء أخطاء الاتصال ظاهرة مع إعادة المحاولة، وتخصيص البيانات التجريبية
  لفتح `file://` أو طلب `?demo=1` صراحةً.
- تفعيل التحقق من نماذج الأدمن والحفظ بـ Enter، وتنظيف مستمع الإغلاق،
  ومنع إظهار تسجيل خروج ناجح إذا فشل الطلب.

## قاعدة المعاينة

كانت نسخة المعاينة المحلية المتاحة عبر Cloudflare قد نُسخت باستخدام
`CREATE TABLE LIKE`، الذي لم ينقل المفاتيح الأجنبية. فُحصت العلاقات الست
بين المستخدمين والجلسات والأندية والمحتوى؛ لم توجد سجلات يتيمة.
أُعيدت العلاقات دون تغيير الصفوف، وصُحح سكربت إنشاء المعاينة لتضمينها
في النسخ اللاحقة. قاعدة العمل الأساسية وكلمات مرورها لم تتغير.

## التحقق

- اختبارات التكامل تستخدم قاعدة `riwaq_test_*` جديدة وبيانات مصطنعة،
  وخادمًا على منفذ محلي مؤقت، ثم تزيل مواردها بعد التشغيل.
- أظهرت الجولة الأولى ست مجموعات فاشلة، ثم نجحت بعد التصحيح.
- جولة المراجعة الأمنية في 2026-10-16: 24 مجموعة اختبار، بينها ثمانية فحوص داخلية للبروكسي
  والجلسات، واختبار متصفح فعلي عبر Microsoft Edge.
- أُعيد إنتاج خمس حالات فشل إضافية قبل الإصلاح: الدخول المتزامن مع
  تغيير كلمة المرور، تعارض معرف النادي، تعارض اسم رئيس النادي، إنشاء
  حسابين للنادي نفسه، وتسريب أخطاء قاعدة البيانات باستجابة نجاح زائفة.
  اختبارات التزامن تستخدم خادمي PHP وقفلًا فعليًا في قاعدة اختبار فقط؛
  لا تعتمد على انتظار زمني تخميني. نجحت الحالات الخمس بعد التصحيح.
- جُرّبت إضافة نادي وحساب، وتغيير كلمة المرور، والنشر من لوحة الرئيس،
  وظهوره للطلاب، ورفض الوصول بين الأدوار والأندية، ورفع صورة حقيقية
  ورفض ملف متنكر، وحذف المحتوى المرتبط، وإبطال الجلسات.
- فُحص عرض الأقسام الثلاثة بعرضي 1440 و390 بكسل، دون تجاوز أفقي،
  وفُحصت لقطات الجوال بصريًا. لم يظهر خطأ JavaScript غير معالج.
- فُحصت الصفحات العامة والدخول بدوري الأدمن والرئيس عبر HTTPS في الرابط
  الحالي، ووجود Secure وHttpOnly في كوكي الجلسة، وحجب الملفات الخاصة.
- نجح فحص تركيب ملفات PHP وJavaScript و`git diff --check`.
- أُعيد تشغيل قاعدة التطوير والخادم المحلي وخادم المعاينة بعد توقفها،
  دون إعادة تهيئة البيانات أو تغيير كلمات المرور. فُحصت علاقات قاعدة
  المعاينة الست مجددًا: كلها موجودة ولا توجد سجلات يتيمة.

## تطوير تجربة الاستخدام

دفعة 2026-10-16 التالية للمراجعة الأمنية، مع الحفاظ على البوابات الثلاث
وكل فحوص الصلاحيات في الخادم:

- الطلاب: بحث في الفعاليات بالعنوان والوصف والمكان والنادي، وفلتر النادي،
  وفصل القادمة عن السابقة، وترتيب حسب التاريخ والوقت، وحالات فارغة واضحة.
- الرؤساء: مسودات مستقلة للمنشور والإعلان والفعالية وحسابات التواصل تحفظ
  أثناء التنقل بين التبويبات، وإرفاق صورة ومعاينتها قبل النشر، والاحتفاظ
  بالمسودة والصورة المرفوعة عند فشل النشر لإعادة المحاولة دون رفع مكرر.
- الأدمن: بحث موحد مع تصنيف النادي وحالة حساب الرئيس، وعدد النتائج،
  ومسح الفلاتر، وتحسين عرض الجدول على الجوال.
- صور المنشورات مرتبطة بملفات رفع موجودة تخص النادي نفسه. لا يقبل الحقل
  الجديد مسارات أو روابط خارجية أو صور نادي آخر؛ لا يوجد تغيير في المخطط.
- أُعيد إنتاج تعليق زر النشر عند إزالة صورة أثناء تجهيز بديل لها، ثم
  أُصلح وأُضيف اختبار متزامن يمنع عودة المشكلة.

التحقق النهائي لهذه الدفعة: **27 مجموعة ناجحة، صفر فشل**، على قاعدة اختبار
مصطنعة ومنفذ مؤقت. يشمل النشر وظهور الصورة للطلاب، فشل الاتصال وإعادة
المحاولة، تنظيف المسودات عند الخروج، الصلاحيات، والتزامن. فُحص العرض عند
1440 و390 و320 بكسل دون تجاوز أفقي، مع مراجعة لقطات الشاشة، ودون أخطاء
JavaScript غير معالجة. نجحت فحوص تركيب PHP وJavaScript، وتطابق JSX
المضمّن، و`git diff --check`.

المسودات مؤقتة داخل الصفحة وليست محفوظة في قاعدة البيانات أو التخزين
المحلي؛ إعادة تحميل الصفحة أو تسجيل الخروج يمسحها. لم تتغير كلمات المرور
أو بيانات العمل في هذه الدفعة.

أُعيد تشغيل الخوادم المحلية والنفق بعد توقفها. فُحصت الصفحات العامة وAPI
للأندية وملفات الواجهة الجديدة، وحجب ملفات الإعداد والاختبار. **لم ينجح
إعادة التحقق من دخول حسابات المعاينة الحقيقية**: بيانات الاعتماد المحفوظة
قديمة، والتحقق المحلي للقراءة فقط أكد أنها لا تطابق البصمات الحالية.
لم نُعد تعيين كلمات المرور. نجاح الدخول عبر HTTPS المذكور سابقًا يخص
الجولة السابقة، وليس تأكيدًا جديدًا لهذه الحسابات على الرابط الحالي.

## حدود التحقق

إعدادات Apache `.htaccess` راجعتها على مستوى الملفات ولم أشغّل Apache
في هذه البيئة؛ التحقق التشغيلي هنا استخدم خادم PHP المحلي والنفق الحالي.
فحص مجلدات XAMPP لم يعثر على `httpd.exe`. يجب تأكيد قواعد Apache ووظيفة
`GET_LOCK` على مزود الاستضافة الفعلي قبل النشر الدائم.
لم تُنفذ مراجعة اختراق شاملة أو اختبارات ضغط. رابط Cloudflare الحالي
نفق مؤقت يعتمد على بقاء جهازك والخادم والنفق قيد التشغيل.
